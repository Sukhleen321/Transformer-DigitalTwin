# Live physics simulation — implementation and local verification

11 October 2026, Asia/Calcutta. This is the user-approved follow-up to Phase 0–7,
under the original canonical physics-first plan. No additional phase, competing
implementation plan, commit, push or deployment was created. Historical reports
and the frozen production physics contract remain unchanged.

## Implementation and boundary

Implemented an opt-in live numerical demonstration in the existing Thermal &
loading panel. A separate producer advances typed synthetic inputs through the
unchanged `PhysicsEstimator`, independently advances a new 2D two-sheet FEM,
calculates an explicitly illustrative ageing index and sensor lag, and writes
timestamped demo events/checkpoints atomically to a separate ledger. GET never
writes. Current-source backend and frontend run as separate owned local
processes against a newly created disposable PostgreSQL database.

The separate versioned GET `/api/v1/demo/transformers/{id}/physics` requires
`PHYSICS_ENABLED=true`, `LIVE_PHYSICS_DEMO_ENABLED=true`, `ENV=local-demo`, and
matching configured/bound `live_physics_demo_<32 hex>` database names. Both flags
default false. Ordinary `/api/v1/transformers/{id}/physics` retains its original
schema/eligibility and does not return demo values. No profiles, operational
configuration, canonical telemetry, empirical analytics, ML checkpoints or
standards ageing results are generated by this demonstration.

Frontend opt-in is `VITE_LIVE_PHYSICS_DEMO_ENABLED=true`. Only that build/process
uses the demo endpoint and 4 s polling while Thermal & loading is active. The
existing fetch base URL, timeout, cancellation, error handling and selected-asset
checks remain in use. Per-asset event/run/sequence watermarks reject older
responses, including after visiting another asset. Loading, errors and stale
events withhold values; an independent display timer expires an event after
15 s even if transport is delayed. Every row explicitly says SYNTHETIC_SIMULATED.
The panel shows LIVE SIMULATION, event/publication/latest-update time, run,
sequence, status, units, target and model provenance. Existing styles and normal
frontend behavior are preserved; no UI redesign or frozen schema weakening.

## Equations, synthetic inputs and numerical limitations

The complete pre-implementation definition is
[live_physics_demo_model.md](live_physics_demo_model.md). Fictional inputs:
Ta=To(0)=Tw(0)=300 K; Ro=0.35 K/W; Rw=0.2 K/W; Co=80 J/K; Cw=40 J/K;
I(t)=10[0.55+0.25 sin(t/20)] A on a declared fictional balanced RMS HV line-current
basis. Existing current-squared loss gives P=6+30(I/10)^2 W at synthetic 300 K
reference; explicit demo partition Po=6 W, Pw=P−6 W. No equipment rating or loss
partition is inferred or published. The existing exact-exponential RC equations
are Co dTo/dt=Po+(Tw−To)/Rw−(To−Ta)/Ro and Cw dTw/dt=Pw−(Tw−To)/Rw.

The fictional sensor is a 5 s first-order lag driven by previous oil-node
temperature. Demo ageing is F=exp[(Tw−310 K)/(20 K)] (unit 1), integrated with
H += (Fprevious+Fcurrent)dt/7200 h for contiguous supported event history. The
reference/scale are illustrative project definitions, not insulation constants
or IEEE/IEC equations. Initial H=0 is zero elapsed demo history. Ageing, RUL and
failure probability remain unavailable through ordinary physics.

The independent FEM uses two overlapping 0.5×0.5 m synthetic sheets, d=0.02 m,
k=2 W/(m K), insulated lateral boundaries, uniform initial 300 K and distributed
ambient/inter-sheet exchange. Its PDE, P1 consistent mass/stiffness assembly,
positive normalized cosine-modulated heat distribution and semidiscrete matrix
exponential are documented in the model definition. Production mesh is 6×6
subdivisions; dense mesh input is bounded to 2–16. These are not real transformer
geometry/materials and do not reuse the Phase 3 manufactured rectangle as a
winding model.

Integrating the two sheet PDEs yields the RC **area-mean** balances. The comparable
target is the winding sheet's area-average temperature, not its spatial maximum.
The two corresponding rows explicitly say winding mean proxy. Difference is RC
winding mean minus FEM winding mean, in K; no temperature offset is applied to
differences. Agreement is a conservation/forcing verification, not fitting,
physical hot-spot validation or real-world accuracy. Relative error of this
near-zero difference is not reported. Tiny signed residuals round to `-0 K` at
the existing three-decimal display precision; the raw nonzero residual is kept
in the API evidence.

Independent insulated cosine diffusion verification produced RMS errors
0.0563718399762, 0.0153099466941 and 0.00391706456859 K on 4, 8 and 16 meshes,
with observed orders 1.8805 and 1.9666. This passes the declared decreasing-error
and final-order >1.5 criterion. Constant patch/source conservation and aligned
RC/FEM means pass their 1e−9 / 1e−8 tolerances. Tests also require a nonuniform
FEM field; common mean agreement does not eliminate spatial variation.

No authoritative full-text standards verification was added. The previous
[physics references](physics_references.md) and unverified IEEE C57.91-2025 /
IEC 60076-7:2018 applicability/equations retain their existing status. No
standards compliance or field accuracy is claimed.

## Reproducible local launch and stop

Prerequisites: existing repository Python environment and dependencies, Node,
`frontend/node_modules`, and a **local** PostgreSQL administrator able to create
and drop databases. Supply `TEST_DATABASE_URL` securely in the shell environment;
its credentials are intentionally omitted here. Its original database is never
migrated or written. The launcher accepts loopback PostgreSQL hosts only.

From the repository root in PowerShell:

```powershell
.venv/Scripts/python.exe backend/scripts/live_physics_demo.py --backend-port 8002 --frontend-port 5177 --interval 4
```

Open the printed frontend URL, choose Monitor LIVE-DEMO-A or LIVE-DEMO-B, then
Thermal & loading. After the first strictly positive interval all ten rows have
numeric values; initialization is explicitly withheld. Defaults are backend
`http://127.0.0.1:8002` and frontend `http://127.0.0.1:5177`. Occupied ports select
the next free port without stopping another service; the printed URLs and exact
CORS origin use that choice. Current frontend API base has no `/api/v1` suffix.
The launcher sets the API URL and demo flag only in its owned Vite process; no
production/deployed environment file, proxy target or CORS configuration changes.

Stop with **Ctrl+C in that launcher shell**. Its `finally` block stops only its
owned backend/producer/Vite children and drops only the newly generated database.
To pause just the owned producer, create `stop-producer` in the printed output
directory; the API/UI then withhold expired values. Still use Ctrl+C to stop the
other two processes and remove the database. A producer restarted directly with
the same run ID/database can restore the last committed state within 30 s;
larger gaps fail closed and need a new disposable launch. Do not kill unrelated
processes or run the migration manually against the original database.


The browser paths are this validation machine's installed tools, not production
source addresses; use your own existing Playwright/Chromium paths. `--verify`
